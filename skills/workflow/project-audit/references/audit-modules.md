# 审计模块完整定义

## 模块一：数据与结果的可追溯性

**目标**：验证关键结果是否能够从现有数据独立追溯和重算。

**检查内容**：
1. 从项目数据起点追溯到最终结果的完整数据流是否清晰
2. 关键统计数字能否由现有数据和代码独立重算
3. 是否存在手工修改、临时脚本、未记录中间步骤、选择性汇报、重复计数或口径漂移
4. 样本数、变异数、分类统计、汇总表和图表数字是否彼此一致
5. 若项目定义了多级筛选结果或不同结果集合，检查其边界和归属是否清晰且可验证
6. 是否存在"孤儿文件"或"断链"

---

## 模块二：代码与流程可靠性

**目标**：验证核心代码逻辑、参数设置和边界处理是否正确。

**检查内容**：
1. 数据读取、过滤、分组、统计、注释、导出流程是否完整且逻辑闭环
2. 关键阈值、筛选条件、分类规则是否实现正确
3. 边界条件错误、缺失值处理错误、硬编码、off-by-one、优先级错误或条件遗漏
4. "魔法数字"或缺少输入验证的关键函数
5. 样本状态分类、筛选等级或世代/处理组逻辑，检查实现与方法描述是否一致
6. 输出文件结构、列定义、命名规则是否与代码实现一致

---

## 模块三：文档与结果一致性

**目标**：确保说明文档、代码、结果文件和图表之间相互一致。

**检查内容**：
1. README、方法说明、配置文件与代码实现是否一致
2. 结果文件、统计表、图表与正文表述是否一致
3. 样本命名、分组定义、阈值参数、版本标识、文件命名是否跨文件统一
4. 同一指标在不同文件中口径不一致的情况

---

## 模块四：方法学合理性

**目标**：评估分析方法是否科学、适用且解释不过度。

**检查内容**：
1. 工具选择、关键参数和参考资源是否与物种特征（倍性、基因组大小、重复序列水平）和研究目标相匹配
2. 阈值设置是否有数据依据、经验依据或文献/最佳实践支持
3. 注释方法、变异分类方法和统计汇总方法是否合理
4. 常用质量指标和生物学指标是否在合理范围内并被谨慎解释
5. 过度解读、因果推断、未经验证的机制解释或超出数据范围的推广
6. "循环论证"（用结果反推参数，再用参数验证结果）

---

## 模块五：结论强度与表述真实性

**目标**：判断结论措辞是否与证据强度匹配。

**检查内容**：
1. 识别所有关键结论，分为三类：
   - **数据直接支持**：有明确的数据和代码直接验证
   - **基于现有结果的合理推断**：逻辑合理但证据强度有限
   - **证据不足或存在夸大风险**：超出数据支持范围
2. 过强表述："证明""确认""明确表明"等
3. 掩盖不确定性的表达：只报告支持性结果而忽略限制条件、反例或负结果
4. 不恰当包装：推测被包装为事实，或实证结果被写得含混
5. "隐含假设"：结论依赖但未明确说明的前提条件

---

## 模块六：可复现性

**目标**：评估第三方是否能够依据现有材料复现主要结果。

**检查内容**：
1. 是否提供足够的输入输出对应关系、脚本、参数、依赖环境和版本信息
2. 是否存在隐藏的手工步骤、临时脚本或未记录操作
3. 软件版本、参考基因组版本、注释版本、数据库版本是否明确
4. 随机过程、并行或随机种子是否影响结果一致性
5. 是否提供了"最小可复现示例"

---

## 模块七：项目交付物与输出目录结构

**目标**：确认项目交付物满足审计、复核和复现所需。

### 最小交付物要求

1. **代码目录**（code/ / scripts/ / bin/）
2. **结果目录**（results/ / output/），至少含机器可读 .tsv
3. **项目说明文档**（README.md）

### 推荐目录结构

```
project_root/
├── code/                    # 主分析代码
├── results/                 # 核心输出结果
│   ├── tsv/                 # 机器可读表格
│   ├── xlsx/                # 人工交付表格（如适用）
│   └── figures/             # 图表（如适用）
├── README.md                # 项目说明文档
└── release/                 # 正式交付包（可选）
```

### 代码目录检查要点
- 能否识别主入口脚本
- 是否存在无法判断用途的脚本
- 关键参数是否集中管理
- 多版本脚本是否标明最终版本
- 是否有 environment.yml / requirements.txt

### 结果目录检查要点
- 是否有标准 .tsv 结果文件
- .xlsx 与 .tsv 是否一致
- 文件命名是否反映类型和版本
- 图表数字是否可追溯到表格

### README 必须说明
1. 项目背景（目的、物种、数据起点）
2. 输入数据（类型、样本定义、参考基因组版本）
3. 分析流程（步骤、工具、审计边界）
4. 筛选逻辑（阈值、条件、结果层级）
5. 输出文件（用途、字段说明、tsv/xlsx 对应）
6. 复现说明（运行命令、依赖版本、手工步骤）
7. 版本信息（分析版本、代码版本、修订历史）

### Release 目录检查（若存在）
- 内容完整性和版本一致性
- MD5 校验和或完整性验证
- 可独立使用性

### 判定原则
- **Critical**：缺少核心交付物或三者无法建立对应关系
- **Major**：交付物存在但版本混乱、关键说明缺失
- **Minor**：基本完整但命名不规范、说明不充分
- **Suggestion**：可进一步规范
